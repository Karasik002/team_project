## AI Smart Recipe Maker – Архітектура

### Мета
Створити веб-платформу, що перетворює перелік наявних інгредієнтів на персоналізовані рецепти з мультимедійною підтримкою, веденням профілю користувача, керуванням запасами та соціальними взаємодіями.

### Технологічний стек
- **Фреймворк**: Next.js 14 (App Router) з TypeScript для SSR/SSG і гнучкого маршрутизаційного шару.
- **Стан**: Zustand + React Query (або нативний кеш Next.js) для локального стану та асинхронних операцій.
- **Стилі**: Tailwind CSS + shadcn/ui компоненти для швидкої розробки адаптивного UI.
- **Сховище**: LocalStorage (демо) з абстракцією `storageService`; передбачено API-шар для підключення до справжнього бекенда.
- **AI інтеграції**: сервісний шар `aiService` із можливістю підключення до LLM-API (OpenAI, Vertex, Cohere). Наразі – детермінована генерація мок-даних.
- **Мультимедіа**: інтеграція з Unsplash/Pexels API (мок) та YouTube/loom links (мок). В реальних умовах – через server actions або edge-функції.
- **Голос**: Web Speech API (клієнт) для диктування та голосових підказок у «кухонному режимі».
- **Barcode**: інтерфейс до QuaggaJS/ZXing; демо-версія використовує симулятор з фіксованими штрих-кодами.

### Основні модулі
1. **Ingredient Input**:
   - Поле текстового вводу + кнопка голосового диктування.
   - Опціонально: імпорт зі штрих-коду/панtry.

2. **Recipe Engine** (`services/recipeEngine.ts`):
   - Приймає інгредієнти, профіль (алергії, дієта, вподобання, історія).
   - Формує список рецептів (назва, опис, етапи, медіа, нутрієнти, поради подачі, економність/залишки).
   - Зберігає історію запитів.

3. **Nutrition & Goals** (`services/nutrition.ts`):
   - Розрахунок калорій та БЖВ на основі бази даних (мок таблиця).
   - Рекомендації відповідно до фітнес-цілей користувача.

4. **Pantry & Shopping**:
   - `pantryStore` керує запасами, термінами придатності, пропозиціями використання залишків.
   - `shoppingListStore` синхронізується з рецептами (додає відсутні інгредієнти).

5. **Gamification** (`services/gamification.ts`):
   - Трекінг досягнень, виклики, система балів.

6. **Social Layer**:
   - Лента рецептів користувачів, рейтинги, коментарі (локальні мок-дані).

7. **Kitchen Assistant Mode**:
   - Повноекранний режим з голосовими підказками, таймерами етапів.

### Сторінки (App Router)
- `/` – Панель: швидкий ввід інгредієнтів, останні рецепти, активні виклики.
- `/recipes` – Список рецептів із фільтрами, деталізація у модалці/окремому маршруті.
- `/recipes/[id]` – Деталізація рецепту, відео, поетапний режим.
- `/profile` – Алергії, дієтичні уподобання, фітнес-цілі, історія.
- `/pantry` – Запаси, штрих-коди, терміни придатності.
- `/shopping-list` – Автоматичний список покупок.
- `/community` – Соціальна зона, рейтинги, обмін рецептами.
- `/challenges` – Гейміфікація, прогрес.

### Дані та сховище
- **Stores**: Zustand ( `useProfileStore`, `usePantryStore`, `useRecipeStore`, `useGamificationStore`, `useCommunityStore`).
- **Persistence**: синхронізація з LocalStorage через middleware; API-інтерфейси (`services/apiClient.ts`) для реальних серверних викликів.
- **Mock Data**: `data/ingredients.ts`, `data/recipes.ts`, `data/community.ts`.

### Взаємодії
1. Користувач вводить інгредієнти → `recipeEngine` генерує рецепти → карта рецептів, кожен зі змодельованими даними.
2. Відсутні інгредієнти визначаються, формують заявку в `shoppingListStore`.
3. Профіль та історія готування впливають на пропозиції (новизна, улюблені, дієта).
4. Gamification зростає при приготуванні/поділі рецептів.

### Мапа компонентів
- `components/IngredientInput` – текст + голос.
- `components/RecipeCard`, `RecipeDetail`, `NutritionBadge`, `CookingSteps`.
- `components/PantryList`, `BarcodeScanner`, `ExpiryAlerts`.
- `components/GamificationWidget`, `ChallengesBoard`.
- `components/SocialFeed`, `RecipeShareModal`.
- `components/KitchenAssistant` – голосовий режим.

### Стратегія реалізації
1. **Скелет проєкту**: ініціалізація Next.js, Tailwind, базові layout/components.
2. **Core Flow**: інгредієнти → рецепти → деталізація.
3. **Профіль та збереження**: Zustand + LocalStorage; форми налаштувань.
4. **Pantry & Shopping**: CRUD запасів, нагадування.
5. **Gamification & Social**: демо-дані, інтеракції.
6. **Kitchen Assistant**: голосовий режим, таймери.
7. **Полірування**: адаптивний дизайн, документація, unit-тести ключових сервісів.

### Мок-інтеграції та точки розширення
- Бекенд-API може бути реалізований окремо (NestJS/FastAPI). UI готовий до заміни мок-сервісів реальними викликами.
- Для розпізнавання штрих-кодів вбудований інтерфейс; достатньо підключити справжню бібліотеку та камеру.
- AI сервіс адаптується під конкретний провайдер (конфігурація через environment variables).

### Тестування
- Unit-тести для сервісів (`vitest` у середовищі Next.js через `ts-jest`/`vitest`).
- Компонентні прев`ю через Storybook (опціонально, не в MVP).
